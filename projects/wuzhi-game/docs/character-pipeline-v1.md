## 三、图片接收规格（你提供参考图时按这个来）

### 必需：四方向静态图（4 张）

| 项目 | 要求 |
|---|---|
| 方向 | 下（正面）、左、右、上（背面），各一张 |
| 格式 | PNG，**透明背景** |
| 画布 | 每张同尺寸，建议 **256×384** 或 **128×192**（我会归一化到 64×96） |
| 内容 | 只有一个角色，完整全身，不裁头不裁脚 |
| 禁止 | 地面、投影、文字、边框、水印、多人合影 |
| 一致性 | 四张同身高、同头身比、同配色、同一套服装 |
| 文件名 | `{character_id}_{appearance_id}_{down,left,right,up}.png`，例：`rudeus_child_down.png` |

### 可选但强烈建议

- 一张**参考立绘/官方截图**：只用于核对发色、服装、配饰，不进游戏。
- 一句时期说明：例「布耶纳村童年，棕发，见习法师装」。

### 关于 4 张静态图能走多远（先说清）

静态图只能得到：**四方向待机 + 由静态图位移/起伏生成的“占位行走”**。

`02` 和 `04` 都写明「手臂和腿动作要真实变化，不能复制粘贴同一张静态图后只挪动身体」。所以：

- 占位行走**只用于跑通链路和验收流程**，状态只能标「待验收」；
- 正式 12 帧仍需逐帧绘制，届时我按同一路径替换 PNG，manifest 和 Godot 场景不用改。

## 四、技术规格（沿用制作包，标出待定项）

| 项目 | 值 | 状态 |
|---|---|---|
| 图集布局 | 3 列 × 4 行 | 锁死 |
| 行序 | down / left / right / up | 锁死 |
| 列序 | 左脚 / 中立 / 右脚 | 锁死 |

## 五、数据模型

```json
{
  "character_id": "rudeus",
  "appearance_id": "child",
  "source_type": "canon_character",
  "display_name": "鲁迪乌斯",
  "batch": "P0",
  "sprite": { "path": "...", "frame_size_px": [64, 96], "columns": 3, "rows": 4 },
  "portrait": { "expressions": ["normal", "smile", "angry", "surprised"] },
  "status": "placeholder | in_review | approved",
  "quality_gates": ["reference_checked", "four_directions_consistent", "foot_anchor_aligned", "in_godot_tested"]
}
```

禁止字段：`age`、`birth_year`、`age_up`、`growth_stage`、`time_to_appearance`。

## 六、首个试点的执行顺序

1. 你给四张 `rudeus_child_*.png`（+ 可选参考立绘）
2. 我校验：尺寸、透明、脚底基线、四向一致性
3. 归一化为 3×4 图集（待机 4 帧 + 占位行走 8 帧）
4. 写 `sprite_manifest.json`
5. 建 Godot 场景：`player.tscn` / `npc_base.tscn`，SpriteFrames 四向待机 + 行走
6. 搭最小测试地图（32px 瓦片假设），验证脚底不漂、转向不翻错、门口遮挡
7. 出截图/录屏 + 状态表；未实测项一律标「待验收」

## 七、验收清单（来自 04 / 02）

- [ ] 身份一致：每个方向认得出同一个人，无时期混搭
- [ ] 尺寸一致：每帧同画布、同显示比例
- [ ] 锚点一致：鞋底落点一致，不切入邻帧
- [ ] 动作一致：左右腿交替，待机停在中立
- [ ] 地图协调：门口、树下、桌椅边不糊不锐
- [ ] 工程可用：透明 PNG、目录命名正确、Godot 4.x 可读取播放
- [ ] 实机：原地四方向、横移、纵移、转身、斜向无滑行抖动
- [ ] 无实机证据时，状态只写「待验收」
