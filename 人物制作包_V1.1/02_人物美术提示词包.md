# 《无职转生：第二人生》人物美术提示词包 V1.1

> 配套文件：`01_人物清单.xlsx`、`03_逐角色提示词.md`、`04_Codex执行指令.md`。  
> **已锁定方向：原有日式RPG瓦片地图继续使用，不改为全高清手绘地图。**  
> 用法：先将参考截图与角色设定交给图像制作工具，再由Codex整理命名、清理帧、导入Godot。Codex的职责是工程集成和资源处理，不应假装凭文字自动产出稳定的专业角色逐帧美术。

> **V1.1 约束：当前不制作时间成长系统。** 每位角色只制作已选定的固定外观；童年、少年、成年等词仅用于原著参考图匹配。不同年龄时期的第二套、第三套外观暂停生产；不根据游戏日期或游玩时长自动替换人物图。

## 0. 使用前必须确认

1. 优先使用游戏现有地图的瓦片尺寸、角色占格比例、相机缩放和纹理过滤；下面64×96是**待验证的候选帧画布**，不是已经确认的现有工程标准。
2. **原著参考图确定“人物是谁”，本包风格母版决定“在地图里长什么样”。** 原著不同时间段的服装和发色绝不能混用。
3. 你先前发的白发精灵图只是**四方向素材形式参考**，不是《无职转生》人物，也不是完成对齐的标准资源。
4. 初始首批只做 `player_custom`、鲁迪乌斯童年、爱丽丝罗亚期、洛琪希导师期、希露菲幼年，以及4种通用NPC；其他批次暂停。
5. 人物美术制作与地图制作解耦，禁止以人物造型为理由整批重做地图。

## 1. 固定画风母版（适用于所有地图小人）

### 正向总提示词

日式奇幻RPG地图用角色精灵，适配已有的轻量像素风瓦片地图，而不是高清手绘背景；
头身比例约2.5～3，形体简洁、轮廓明确、低细节密度；发型和服装主色保留角色识别点；
像素笔触与地图统一、有限色阶的简洁阴影（每个主要材质约2～3档明暗），不要过密高光、发丝纹理；
固定斜俯视正交RPG人物视角，不使用明显的真实透视；纯透明背景，无地板、无投影贴图、无文字。

### 栅格与动作硬约束

布局：3列×4行；行序（上→下）：下/左/右/上；列序（左→右）：左脚迈出/待机中立/右脚迈出。
每帧画布候选64×96像素，整图192×384像素；实际项目接入前先依据Godot地图格尺寸确认。
全部帧以人物脚底触地点对齐到本帧同一基线，统一相机、缩放、身体宽高、头部相对位置。
手臂和腿动作要真实变化，不能复制粘贴同一张静态图片后只挪动身体。
导出透明PNG，邻帧不重叠；如AI无法做到准确帧对齐，先输出四方向静态转身参考，再逐帧人工修正。

### 通用负面提示词

错误方向、不一致的鞋/头发/服装、多出手脚、四方向不匹配、脚底位置漂移、
不同帧比例变化、背景、地面、投影烘焙、文字、UI边框、水印、残影、
刺眼赛博朋克色彩、3D光泽、写真皮肤、复杂反射、写实发丝、伪像素噪点、
过度Q版一头身、整张高清立绘直接缩小、过度模糊、无规律的像素锯齿。

**推荐顺序：** 单角色静态正面→背面→左/右侧面→动作关键帧→透明帧精修→自动/人工对齐→Godot播放测试。

## 3. 剧情立绘（独立于地图小人）

剧情对话人物立绘；使用同一角色设定表；标准日式动漫奇幻插画，完整头发与服装轮廓，
角色头部+半身或大半身，透明背景，统一眼睛/脸型/发色/服装；
基础表情：普通、微笑、惊讶、生气；重要人物可追加悲伤、害羞等；
先做一个无表情基底版本，再派生表情图，避免每张立绘都出现服装变化。

```text
《无职转生：第二人生》剧情对话立绘：{角色名} / {时期}。
保持原著角色辨识度，参照用户提供的对应时期外观截图。
标准日式动漫奇幻立绘；半身，透明背景，画面不包含文字。
本次表情：{normal/smile/angry/surprised/sad}。
同角色的所有表情共享同一服装、姿态、头部大小与画面裁切；禁止随机换脸。
```

- 建议先制作 `normal` 母版，表情派生基于母版进行局部修改。
- 立绘分辨率只作为输出规格，不强制要求地图人物采用相同清晰度。
- 普通NPC优先使用统一头像框的头像资源，不需要完整立绘。

## 4. 战斗人物（暂缓至系统进入演出开发）

2D战斗演出角色，与地图人物识别点一致，体型细节可以较高但不改变人物设定；
支持待机、攻击准备、攻击关键帧、受击、施法（若适用）、胜利/倒地；
武器、魔法特效与角色身体分层；脚底基准点一致；不强制以地图行走图直接充当战斗图。

```text
2D日式奇幻RPG战斗角色【{角色名}】 / {时期} / {动作}。
保持地图角色同一发型、服装、配色与体型设定。
动作需包含准备姿态、关键动作、恢复姿态三个节奏阶段（可按需要增加帧）。
导出透明背景，身体、武器、元素特效分开；禁止将火焰/法阵永久画到人物衣服上。
先用灰盒角色+技能特效验证战斗流程，再做正式战斗动作资源。
```

## 5. 高清参考转换为项目画风的操作提示词

```text
输入：一组原著角色参考图 + 已通过验收的项目标准地图人物母版。
目标：提取角色识别点并重绘为项目统一的低细节日式RPG小人。
要求：保留发型剪影、主色、标志性服装和装备；简化脸部高光、复杂发丝、印花。
不要只对原始高清图进行像素化滤镜、模糊缩放或自动马赛克；
必须重新梳理轮廓和光影，使角色与现有瓦片地图统一。
先给正面待机，再给四方向，最后才生成动作序列。
```

## 6. 帧修复专用提示词 / Codex任务

```text
现有角色素材为3列×4行的四方向行走图。
请先检测每帧非透明像素边界；不要假设现有图一定按几何等分正确裁好。
逐帧提取时避免切入相邻帧的发丝/披风。统一脚底基线与身体中心，
补透明边距并重新排版为合法图集；输出帧占位矩形、脚底位置和检查报告。
复用顺序为“中立→左脚→中立→右脚”；不得改变原有角色脸部与服装设计。
Godot内对比测试：原地动画、水平移动、竖直移动、180°转身、斜向输入、
不同相机缩放下的闪烁/抖动及动画移动速度匹配。
```

## 7. 美术验收：必须满足

- **身份一致**：每个方向认得出同一个人；原著角色时期无混搭。
- **尺寸一致**：每帧使用相同画布和同一显示比例；当前每人只需验收一套选定外观。
- **锚点一致**：鞋底落点一致；脚和衣服不会切到隔壁帧。
- **动作一致**：左右腿确实交替，待机能正常停在中立姿势。
- **地图协调**：建筑门口、树下、桌椅边测试，人物并不过度锐利或过度模糊。
- **工程可用**：透明PNG、目录命名正确、Godot 4.x场景可读取和播放。

## 8. 不同开发阶段怎么做

- **P0：可玩性验证**。一个玩家角色 + 四名重点角色 + 4种通用NPC；只做地图行走和基础立绘。
- **P1：第一批地图上线**。添加导师、家人、公会和店铺相关NPC。
- **P2：主要冒险剧情扩展**。增加不同地区所需的新角色与NPC；人物多年龄外观继续暂缓。
- **P3：后期剧情/大场面**。制作新出场的特殊角色及必要战斗演出；不自动启用年龄成长。

## 9. 文件命名与导入原则

```text
characters/
  references/{character_id}/{stage_id}/    # 仅参考，不作为游戏成品
  overworld/{character_id}/{stage_id}/
    walk_4dir_3f.png
    sprite_manifest.json
  portraits/{character_id}/{stage_id}/
    normal.png
    smile.png
    angry.png
  battle/{character_id}/{stage_id}/
    idle/
    attack/
  npc_templates/{template_id}/
```

推荐动画名称：`idle_down`, `idle_left`, `idle_right`, `idle_up`,
`walk_down`, `walk_left`, `walk_right`, `walk_up`。

留心：如果想把资源用于公开发布，必须事先确认原著角色形象、官方截图和素材的授权条件；
本包只提供自制项目的规划与制作提示词，不附带任何官方角色图的版权授权。
