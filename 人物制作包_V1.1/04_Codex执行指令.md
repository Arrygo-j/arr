# Codex执行指令｜人物制作包 V1.1（无时间成长）

## 直接复制给 Codex 的总指令

```text
你正在维护Godot 4.x项目《无职转生：第二人生》。
这次任务不是重做地图，而是建立可以反复复用的人物资源系统。

外部资料：
- 01_人物清单.xlsx：人物主表、29项外观资料（其中7项已暂缓）、12种NPC模板、技术规格。
- 02_人物美术提示词包.md：角色风格、12帧规范、验收规则。
- 03_逐角色提示词.md：具体角色风格锚点。
- 05_角色资源样例.json：数据格式参考（需要按项目实际目录调整）。
已有的地图包和Godot工程是最高优先级的兼容约束。

重要：
- **当前不开发时间成长：不要生成日历/年龄计时逻辑，不要按天数/年数自动切换人物外观，也不要因为年龄改动身高、动作和剧情事件。**
- 每个人物在当前阶段只保留所选固定外观；童年、罗亚等是静态参考标签。7项多时期外观资料暂缓，不批量制作。
- 地图风格必须保持原来的日式RPG瓦片风格。
- 不要自动把地图升级到高清手绘，也不要调整地理布局。
- 不要把用户先前的高清白发Q版示例图当成原著角色。
- 不允许直接使用未经用户确认的网页图片当正式角色资源。
- 无法可靠制作的角色美术用清楚标注的临时图，不能声称资源已完成。
- 凡涉及人物时期外观，先检查对应reference图片，再确认制作。

第一步：无破坏检查
1. 列出Godot版本、当前目录、项目地图格尺寸、Display/window缩放、Camera2D、纹理过滤。
2. 查找已有Player/NPC场景、CharacterBody2D移动脚本、AnimatedSprite2D。
3. 不修改旧场景前先创建测试分支或备份，列出将要改动的路径。
4. 检查是否存在统一的资源加载、对话和交互接口；优先复用。

第二步：制作角色资源标准
1. 根据既有瓦片地图确定人物显示高度、真实像素密度与视角。
2. 使用64x96每帧/3列4行作为候选测试方案，必须确认后才定稿。
3. 图片行方向依次down/left/right/up；每行三帧：左脚/中立/右脚。
4. 校验全部透明边界、身体中心、脚底锚点；自动裁切时防止切入相邻帧。
5. 输出完整标准角色图：walk_4dir_3f.png、sprite_manifest.json。
6. SpriteFrames依次映射正交行走；循环推荐中立-左脚-中立-右脚。
7. PNG可读取、透明，纹理过滤按地图和人物的像素属性分别配置。

第三步：完成P0原型人物

npc_guard:town
npc_merchant:market

注意此阶段仅使用用户已经提供或经过确认的参考图；
如缺图则创建占位任务，不要猜测复杂服装。

第四步：Godot集成
1. 创建独立可复用的Player和NPC场景，首选CharacterBody2D。
2. 保留正确的移动、碰撞、NPC朝向、交互、对话调用、Y排序。
3. 对话与人物资源解耦，NPC使用稳定character_id、appearance_id。
4. 对待机和四方向行走建SpriteFrames；切换动画时不要每帧重新play重置。
5. 保留portrait_id、battle_asset_id和当前固定appearance_id；可以通过人工配置选择初始外观，但不实现年龄/时间驱动的切换函数。
6. 加入统一人物阴影（若使用）要作为独立节点，不烘焙进人物图。
7. 用户原有游戏人物系统若更成熟，只适配接口，避免重复建设。

第五步：流畅度验收
- 单角色原地播放所有方向动画，脚底无漂移。
- 平面横移、纵移、转向；检查人物是否滑行、身体是否左右跳。
- 玩家停止移动时进入待机，原地转向不会翻错。
- 避免velocity重复乘delta；按Godot CharacterBody2D方式移动。
- 比较相机跟随与物理插值影响，不将实际FPS问题错当素材问题。
- 用一个建筑门口和一个室内桌椅场景检验尺寸、遮挡、碰撞。
- 验收通过后记录具体帧规格、显示比例、贴图设置。
- 未通过不启动批量生产P1/P2/P3。

第六步：交付
- 输出文件变动清单
- 输出最终资源规格与预估复用量
- 输出P0人物已完成/缺参考图/待验收状态表
- 截图/视频展示原地四方向与地图实际行走
- 列出所有尚未解决的问题
```

## 固定外观数据模型（当前版本）

- `character_id`：角色稳定ID，例如 `eris`。
- `appearance_id`：固定外观资源标识，例如 `roa`；由配置/场景指定，禁止读取游戏时间计算。
- `asset_type`：`overworld`、`portrait`、`battle`。
- 对话绑定的是 `character_id` + `portrait_expression`，而不是固定某张贴图的绝对路径。
- NPC生成点归地图管理，角色本身归人物资源管理。
- 暂不定义 `age`, `birth_year`, `age_up`, `growth_stage`, `time_to_appearance` 等会带来自动年龄演化的运行时字段或系统。

## 特别验收：无时间成长

- 游戏推进、休息、旅行或存档加载，不会让角色外观因游戏天数自动变化。
- P0 每名角色只制作一个已确定的静态形象，不新增童年/少年/成年切换任务。
- 后续如需手动换服装，可另开独立需求，不与角色年龄挂钩。

## 本包的验收门槛

1. 原地图布局、风格、资源未被重画或批量替换。
2. 角色的帧切分合理、脚底锚点正确。
3. 游戏运行不出现明显滑行、换帧跳动、频繁回待机。
4. P0至少一个人物完成地图实测。
5. 角色来源与游戏原创内容分开记录。
6. 无截图/视频实测时，进度状态只写“待验收”，不能写“已完成”。
